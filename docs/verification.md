## Исправления

1. API больше не сравнивает разные временные сетки, цели доступности или состав/координаты клиентов. Иначе сравнение могло объявить победителя на несопоставимых данных. Названия пунктов и порядок списка могут различаться; изменение ISL и орбит допускается.
2. Сравнение одного запуска с самим собой отклоняется. При переданном `run_ids` проверяется именно этот список.
3. При равной частоте нескольких ведущих причин перерыва `dominant reason` отсутствует: раньше результат зависел от порядка обхода Go map.
4. Фронтенд проверяет одинаковую целевую доступность до запроса сравнения.
5. Редактор времени сохраняет дробные секунды отказов.
6. Сравнение показывает малые изменения координат и слотов спутников, которые раньше терялись при округлении до двух знаков.
7. В проверочном Docker-окружении отсутствие Python-геометрии завершает интеграционные тесты ошибкой вместо скрытого пропуска.

Ошибки сравнения и выбора причины воспроизведены падающими регрессионными тестами до исправления.

## Как повторить

Из корня репозитория в PowerShell:

```powershell
docker build -f Dockerfile.verify -t kosmohak-tests .
docker run --rm --mount "type=bind,source=$PWD,target=/src" kosmohak-tests
docker compose -p kosmohak-ui -f frontend/compose.yml up -d --build
```

При установленном Node.js из `frontend`: `npm ci`, `npm test`, `npm run build`. Для браузерного прогона установить Chromium командой `npx playwright install chromium`, затем `npm run test:e2e`. По умолчанию используется `http://localhost:5173`.

## Границы проверки

- Проверено локальное Docker-развёртывание. Публичный адрес и презентация для сдачи задачи требуют отдельной подготовки.
- Браузерные проверки выполнены в Chromium с программным WebGL; Safari/Firefox и физические мобильные устройства не проверялись.
- Это функциональная проверка комплектных сценариев и граничных случаев, без нагрузочного тестирования большого числа одновременных пользователей.
- Серверные репозитории хранят проекты/прогоны в памяти. Браузер сохраняет варианты и результаты локально; постоянная общая база данных не реализована.
- При полном отказе шлюзов шкала показывает отдельное состояние «Шлюзы недоступны». Из одной причины этого перерыва нельзя заключить, виден ли спутник; агрегированная видимость считается отдельно.
- Сборка предупреждает о размере лениво загружаемого Three.js-модуля около 503 кБ до gzip. Это не ошибка сборки.
- Автоматический поиск оптимальной группировки не подменяется сравнением: приложение оценивает заданные пользователем варианты.

Изменения проверки и исправления оставлены локально, без коммита и push.
