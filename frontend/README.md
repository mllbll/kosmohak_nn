# Орбитальная сеть — frontend

React + TypeScript + Vite. Четыре раздела: проект, отказы, состояние сети, сравнение.
Интерактивные 2D-карта и 3D-глобус используют общие координаты снимка API.
Географические данные Natural Earth входят в сборку через world-atlas; внешние картографические сервисы и ключи не нужны.

## Запуск всего приложения (Docker)

Из корня репозитория:

```sh
docker compose -p kosmohak-ui -f frontend/compose.yml up -d --build
```

Интерфейс: http://localhost:5173. API: http://localhost:8080.
Остановка:

```sh
docker compose -p kosmohak-ui -f frontend/compose.yml down
```

Существующие исходники и Docker-конфигурация бэкенда не изменены.
Отдельный compose-файл собирает тот же бэкенд и nginx с фронтендом.

## Разработка (Node.js 22.12+)

Запустите бэкенд по инструкции в корневом README. Затем:

```sh
cd frontend
npm ci
npm run dev
```

Vite проксирует /api и /health на localhost:8080.
Переменная API_PROXY_TARGET меняет адрес прокси в режиме разработки.
VITE_API_URL задаёт прямой адрес API при сборке (по умолчанию используется текущий origin).
В production nginx проксирует API на сервис api:8080 с таймаутом 310 секунд.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Для браузерных тестов нужен запущенный сервис на localhost:5173 и установленный Chromium:
`npx playwright install chromium`.
E2E_BASE_URL переопределяет URL приложения. E2E-тесты создают отдельные проекты в локальном API.

## Сценарии

1. Выберите одну из четырёх фикстур или загрузите проект JSON.
2. Измените очередь, RAAN, фазу, условия расчёта или координаты пунктов.
3. При необходимости задайте недоступность спутника или шлюза во вкладке «Отказы».
4. Запустите расчёт. До завершения индикатор не показывает выдуманный процент прогресса.
5. Выберите пункт, время и режим карты. Нажатие на интервал переносит к его началу.
6. Измените конфигурацию и выполните новый расчёт. Сравните два прогона на общей временной сетке.
7. Скачайте проект для повторной загрузки или результат со сценарием, маршрутами и метриками.

## Хранение и API

- Варианты сохраняются в localStorage, полные результаты — в IndexedDB.
- API не имеет списка проектов: список поддерживает браузер.
- Сохранение изменённого варианта создаёт новый серверный проект целиком. Это позволяет менять поля, которые PATCH API не поддерживает, и сохраняет старые расчёты.
- Бэкенд хранит проекты и прогоны в памяти. После его перезапуска локальные результаты остаются, но снимки и серверное заключение требуют повторного расчёта. Новый запуск автоматически восстанавливает проект при 404.
- Результаты не подменяются демонстрационными числами.
- Спутники отображаются по координатам API; орбитальные направляющие — геометрическая иллюстрация плоскостей, не отдельный расчёт доступности.
- 3D использует WebGL; при недоступности предлагается 2D. В 3D Земля закрывает объекты на обратной стороне.
- Временная шкала ограничена последним отсчётом, а полосы включают весь представляемый им интервал.
- Для сравнения нужны одинаковые сетка времени и клиентские пункты. Изменения условий и отказов явно перечислены.
- На карте различаются работающий спутник, отказ и аппарат, ещё не введённый в группировку.
- Изображения согласованного дизайна использованы как визуальная спецификация; иллюстративные числа из них в приложение не перенесены.

## Географические данные

world-atlas (ISC) содержит данные Natural Earth, находящиеся в общественном достоянии.
Подложка используется для ориентации; результат геометрической модели определяется координатами сценария и сервера.
