# Орбитальная сеть — КосмоХакатон NN

Веб-приложение для проектирования устойчивой спутниковой группировки. Позволяет настроить орбиты и этап развёртывания, задать отказы спутников и шлюзов, рассчитать доступность связи и сравнить варианты.

Основная задача — оценить наличие пути **наземный клиент → спутники → шлюз** и достижение целевой доступности для каждого клиентского пункта. В комплектных сценариях целевой уровень — **90%**. Видимость спутника и доступность сквозного маршрута оцениваются отдельно.

## Быстрый запуск

Нужен Docker с Docker Compose. Из корня репозитория:

```bash
docker compose up -d --build
```

- **Интерфейс:** http://localhost:5173
- **API:** http://localhost:8080
- **Проверка API:** http://localhost:8080/health

Команда собирает оба сервиса: Go API с Python/NumPy и фронтенд за nginx. Устанавливать Go, Python и Node.js на хост для этого не требуется.

Остановка:

```bash
docker compose down
```

Подробности: [Docker и развёртывание](docs/docker.md).

## Возможности интерфейса

| Вкладка | Возможности |
|---|---|
| **Проект** | Выбор сценария или импорт JSON; настройка орбит, RAAN, фаз, очереди запуска, периода и шага расчёта; сохранение вариантов и сброс изменений. |
| **Отказы** | Добавление и редактирование интервалов недоступности спутников и шлюзов. |
| **Состояние сети** | 2D-карта и 3D-глобус; спутники, наземные пункты, орбиты, связи и выбранный маршрут; временная шкала, симуляция и диаграмма доступности. |
| **Сравнение** | Изменённые параметры, показатели вариантов, достижение целевой доступности, выводы и экспорт сравнения. |

Интерфейс сообщает об ошибках входных данных и отмечает результаты, рассчитанные до изменения настроек. Проект и результаты можно экспортировать в JSON.

### Шаг симуляции и шаг расчёта

Во вкладке **«Состояние сети»** шаг симуляции вводится в секундах:

- `1` — переход на одну секунду. Поддерживаются другие положительные значения, включая дробные.
- `0` — плавное движение со скоростью времени 1×. Координаты, контакты и кратчайший маршрут обновляются в браузере по той же модели, что используется на сервере.

Временная полоска синхронизирована с показанным состоянием карты. При загрузке следующего снимка текущая карта сохраняется.

**Шаг расчёта** задаётся во вкладке **«Проект»** и определяет точность итоговых метрик и диаграммы доступности. Изменение шага симуляции не пересчитывает статистику. Для более подробных метрик уменьшите шаг расчёта и запустите новый расчёт.

## Как провести эксперимент

1. Выберите «Полная группировка» либо загрузите свой JSON.
2. Настройте проект и нажмите **«Запустить расчёт»**.
3. Во вкладке **«Состояние сети»** выберите клиентский пункт, рассмотрите маршрут и доступность связи во времени.
4. Сохраните исходный вариант. Измените параметры или задайте отказы, затем выполните новый расчёт.
5. Во вкладке **«Сравнение»** выберите два результата, изучите различия и экспортируйте данные.

Для корректного сравнения нужны одинаковые период, шаг расчёта, целевая доступность, состав и координаты клиентских пунктов.

## Комплектные сценарии

Исходные данные находятся в [data/](data/). Их копии доступны в интерфейсе без загрузки файлов вручную.

| Сценарий | Что проверяет |
|---|---|
| [Полная группировка](data/01_full_constellation.json) | Работа всех 48 спутников в трёх орбитальных плоскостях. |
| [Первая очередь запуска](data/02_first_launch.json) | Частичное развёртывание — 16 спутников. |
| [Отказы спутников](data/03_satellite_outages.json) | Устойчивость при недоступности десяти аппаратов. |
| [Дальность ISL 2000 км](data/04_link_range.json) | Влияние ограничения межспутниковой связи на сквозные маршруты. |

Форматы: `cosmo-A-1.0` для проекта и `cosmo-A-result-1.0` для результата. Экспорт результата содержит эффективную конфигурацию и маршруты; его можно импортировать как основу нового проекта.

## Устройство проекта

```text
frontend/          React + TypeScript + Vite; 2D-карта и 3D-глобус
cmd/               Точка входа Go API
internal/          HTTP API, бизнес-логика, маршрутизация и хранение
python/            Геометрия орбит и контактов, запуск расчётного модуля
data/              Комплектные сценарии
docs/              Документация бэкенда, API и развёртывания
docker-compose.yml Запуск всего приложения
Dockerfile.verify  Окружение тестов Go и Python
```

Фронтенд использует Three.js для 3D и D3 Geo для 2D. Географические данные входят в сборку; ключи внешних картографических сервисов не нужны. Сервер написан на Go, геометрия рассчитывается на Python с NumPy.

Модель использует круговые орбиты и сферическую Землю. Доступность означает геометрическую возможность передачи по сети; она не является оценкой пропускной способности радиоканала. Наземные клиентские пункты не ретранслируют трафик.

Сервер хранит проекты и расчёты **в памяти процесса**: при перезапуске они удаляются. Интерфейс сохраняет варианты и результаты в браузере. Для переноса между устройствами используйте экспорт JSON. Авторизация и общая постоянная база данных не реализованы.

## Разработка и тесты

Для запуска без Docker см. [разработку фронтенда](frontend/README.md) и [документацию бэкенда](docs/backend.md).

При установленных Go, Python с NumPy и Node.js:

```bash
# Из корня репозитория
python3 -m unittest discover -s python -v
go test -race -count=1 ./...

# Из frontend/
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерным тестам нужно работающее приложение на `http://localhost:5173`. Другой адрес задаётся через `E2E_BASE_URL`. Проверки охватывают сценарии API, карты, отказы, сравнение, секундную и плавную симуляцию, а также соответствие браузерной геометрии серверной.
